# Lessons from feat/open-sdk (open SDK export and docs, 2026-09-27)

- [cyc-licensing-and-release] Before building the exporter, dry-run it: copy every tracked file whose `tierOf()` is open into a scratch dir (filter manifest, save-state index and goldens to open ROMs, symlink the root node_modules) and run `node tools/test-tier.ts node` there with `tools/slot.ts --dir <git common dir>/cyc-slots`; the failures are the real blocker list — evidence: blockers 3/4/5 went from 14 failing tests to 0 in one pass, and build-roms/budget/replay needed no change — scope: until tools/export-open.ts exists
- [cyc-licensing-and-release] Open-tier tests must pass on a tree without the games: assert the manifest, fixture index and goldens agree with each other both ways (set equality) instead of `length >= N` counts, and pick open ROMs (lantern-test, lantern-scrim, sound-test, slice-test) as test subjects — evidence: savestate, savestate-v1, golden-frames, machine-speed tests — scope: always
- [cyc-licensing-and-release] A replay follows its ROM's tier: slice-test is OPEN-CODE, so `replays/slice-test*` needed its own row (the `replays/` default is FIRST-PARTY GAMES) — evidence: dry run lacked the replay, so the slice-test v1 fixture and goldens failed — scope: always
- [cyc-canon] Open docs check against `loadPublicCanon()` (canon/canon-public.json, regenerated by `npm run canon -- --write-public`, tested equal to `extractPublicCanon(canon.json)`); a new date or person in the manual must be in the extract or the open tree's manual test fails — evidence: tests/canon.test.ts, tests/manual*.test.ts — scope: always
- [cyc-licensing-and-release] Keep one text for both trees and let the export prove it clean: the leak scan's terms come from the tier map (closed paths, held-back paths), the manifest (closed ROM names) and canon.json lore minus canon-public.json, so a new closed file or title is caught without editing a list; an allowance needs a reason and fails when it matches nothing — evidence: tools/export-open.ts, tests/export-open.test.ts — scope: always
- [cyc-verify] A step that depends on nearly every file (the open export) cannot sit in a skippable CI part: the ci-impact SAFE proof rejects it (it reads package.json and names tools/), and no path would be safe for it anyway; put it in the static part — evidence: verify step 11, tests/ci-impact.test.ts — scope: always
- [cyc-verify] Code shared by the monorepo and the export decides by an explicit marker (EXPORT.json → TREE = "open"), never by which files happen to exist; plan() takes the tree as an option so tests assert both plans — evidence: tools/verify.ts, tests/verify-parts.test.ts — scope: always
- [cyc-outsider-review] For an SDK or tutorial review, give the reviewer a fresh export copy outside the repository (node tools/export-open.ts <scratch dir>, node_modules removed) and ask it to walk every command on paper against the tools' sources; it found three blocking gaps no test had (an output folder never created, excerpts out of file order, lines claimed quoted but not) — evidence: research/sdk-review.md — scope: always
- [cyc-outsider-review] Turn each "the page quotes X" claim into a coverage/order test over the page's sample markers (tools/doc-check.ts sampleRanges), or the claim drifts — evidence: tests/example-tutorial-1.test.ts, tests/example-tutorial-2.test.ts — scope: always
- [cyc-verify] A docs page that shows code must be built from the same files the tests run: sample markers + doc-check caught every excerpt that went stale during the review fixes (line shifts after an import) — evidence: docs/guide/testing.md sample of tests/example-tutorial-1.test.ts — scope: always
